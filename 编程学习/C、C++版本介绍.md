**结论先明确**：GNU C++（GCC）**并非所有版本都默认支持C++11**，默认启用的C++标准取决于GCC的版本——**GCC 6.1及以上默认启用C++14**，更早的版本（GCC 4.7~6.0）默认仍为C++98/C++03，需手动指定`-std=c++11`。 ### 一、GCC不同版本的C++默认标准 | GCC版本 | 默认C++标准 | 备注 | |---------------|-------------|----------------------------------------------------------------------| | GCC 4.6及更早 | C++98 | 仅部分支持C++11特性，需手动加`-std=c++0x`（早期C++11的临时参数）| | GCC 4.7~6.0 | C++98 | 全面支持C++11，但默认未开启，需`-std=c++11` | | GCC 6.1~10.x | C++14 | 默认启用C++14，同时完全兼容C++11，可通过`-std=c++11`切回 | | GCC 11及以上 | C++17 | 新版GCC默认升级为C++17，需`-std=c++20`/`-std=c++23`开启更高版本 | > 补充： > - 若想强制使用“纯标准C++”（禁用GNU扩展），可加参数`-std=c++11 -pedantic`； > - 若想使用GNU扩展版的C++标准（默认行为），参数为`-std=gnu++11`（区别于纯标准的`-std=c++11`）。 ### 二、如何快速验证当前默认C++标准？ 可以写一段简单的代码，通过`__cplusplus`宏判断（该宏会返回对应标准的版本号）： ```cpp #include <iostream> int main() { std::cout << __cplusplus << std::endl; return 0; } ``` 编译运行结果对应关系： - `199711L` → C++98/C++03 - `201103L` → C++11 - `201402L` → C++14 - `201703L` → C++17 - `202002L` → C++20 ### 三、实操建议 1. **不要依赖默认标准**：跨平台/跨编译器开发时，**显式指定`-std=c++xx`**（如`-std=c++17`），避免不同GCC版本的默认行为差异； 2. **最低兼容要求**：若需兼容老版本GCC（如4.8），建议指定`-std=c++11`（GCC 4.8已全面支持C++11）； 3. **新版开发**：优先用`-std=c++17`（兼容性和特性平衡最好），若需C++20的模块/协程，再指定`-std=c++20`。 简言之，“GNU C++默认支持C++11”是**不准确的**——只有手动指定参数，或使用GCC 6.1+（默认C++14，向下兼容C++11）时，才能稳定使用C++11特性。

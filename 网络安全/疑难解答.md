# Q5:apache配置php5,php3,pht,phtml以php解析

|方式|典型环境|原理|核心配置示例|
|---|---|---|---|
|**mod_php** (`php_module`)|`php5.2.17` + `apache2.2`|PHP 作为 Apache 的一个内部模块运行|`AddType application/x-httpd-php .php .php3 .php5 .phtml`|
|**PHP-FPM + mod_proxy_fcgi**|`php7/8` + `apache2.4`|PHP 作为独立进程池，通过 FastCGI 协议与 Apache 通信|`SetHandler "proxy:fcgi://127.0.0.1:9000"`|
|**CGI/FastCGI** (`mod_fcgid`)|`php5.2.17` + `apache2.4`|PHP 通过 CGI/FastCGI 协议运行，支持多版本共存|`FcgidWrapper "path/to/php-cgi.exe" .php`|

---

#### 1. mod_php (Apache Module 模式)

**原理：**  
PHP 解释器被编译为动态链接库（如 `php5apache2_2.dll`），直接嵌入到 Apache 的工作进程中。Apache 接收到 `.php` 请求时，直接在当前进程内部调用 PHP 模块执行代码，无需跨进程通信。

**特点：**

- **优点**：配置极简，无进程间通信开销，单机低并发下响应极快。
- **缺点**：内存占用高（所有 Apache 进程均需加载 PHP 环境）；**不支持多 PHP 版本共存**；PHP 崩溃会直接导致 Apache 进程崩溃。

**配置示例：**

```apache
1# 加载 PHP 模块
2LoadModule php5_module "D:/phpstudy_pro/Extensions/php/php5.2.17nts/php5apache2_2.dll"
3
4# 指定 PHP 配置文件路径
5PHPIniDir "D:/phpstudy_pro/Extensions/php/php5.2.17nts"
6
7# 将特定后缀交给 PHP 模块处理
8AddType application/x-httpd-php .php .php3 .php5 .phtml
```

---

#### 2. PHP-FPM + mod_proxy_fcgi (现代主流模式)

**原理：**  
PHP-FPM（FastCGI Process Manager）是一个独立的守护进程，负责管理 PHP 进程池。Apache 自身不解析 PHP，而是通过 `mod_proxy_fcgi` 模块，将 `.php` 请求通过 FastCGI 协议转发给 PHP-FPM 监听的端口（如 9000）或 Unix Socket，PHP-FPM 执行完毕后将结果返回给 Apache。

**特点：**

- **优点**：Web 服务器与 PHP 完全解耦；支持平滑重启、动态进程管理；支持多版本共存与分布式部署；高并发下资源利用率极高。
- **缺点**：配置相对复杂，涉及两个独立服务的配置。

**配置示例：**

```apache
1# 确保加载了以下模块
2LoadModule proxy_module modules/mod_proxy.so
3LoadModule proxy_fcgi_module modules/mod_proxy_fcgi.so
4
5<VirtualHost *:80>
6    DocumentRoot "D:/phpstudy_pro/WWW/site"
7    ServerName site.local
8    
9    # 将所有 .php 请求代理给 PHP-FPM (假设 FPM 监听 9000 端口)
10    <FilesMatch \.php$>
11        SetHandler "proxy:fcgi://127.0.0.1:9000"
12    </FilesMatch>
13</VirtualHost>
```

---

#### 3. CGI/FastCGI (mod_fcgid 模式)

**原理：**  
Apache 通过 `mod_fcgid` 模块与外部的 `php-cgi.exe` 进程通信。`mod_fcgid` 维护一个 FastCGI 进程池，当遇到动态请求时，将请求分发给池中空闲的 `php-cgi.exe` 进程处理，处理完毕后进程不销毁，而是留在池中等待下一个请求。

**特点：**

- **优点**：通过 `FcgidWrapper` 可灵活实现**多 PHP 版本共存**（按后缀或虚拟主机区分）；PHP 崩溃不影响 Apache 主进程；比传统 CGI 性能高，比 mod_php 省内存。
- **缺点**：存在跨进程通信开销，极高并发下理论极限性能略低于 mod_php。

**配置示例（多版本共存）：**

```apache
1# 1. 声明多种后缀都交给 fcgid 处理
2AddHandler fcgid-script .php .php5
3
4# 2. 为 .php5 指定老版本执行器
5FcgidWrapper "D:/phpstudy_pro/Extensions/php/php5.2.17nts/php-cgi.exe" .php5
6
7# 3. 为 .php 指定新版本执行器
8FcgidWrapper "D:/phpstudy_pro/Extensions/php/php8.2.0nts/php-cgi.exe" .php
9
10# 4. 确保目录允许执行 CGI
11<Directory "D:/phpstudy_pro/WWW">
12    Options FollowSymLinks ExecCGI
13    AllowOverride All
14    Require all granted
15</Directory>
```
